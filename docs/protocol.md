# 評価プロトコル

舟券ラボの回収率は、このルールで計算します。どの舟券を母数に入れるかで回収率は簡単に歪むので、実装（[`settle.ts`](../packages/core/src/settle.ts)・[`strategy.ts`](../packages/core/src/strategy.ts)）と同じ粒度で書いておきます。

## 1. 締切前に見えていた情報だけで買う

- 戦略が受け取るのは `PreRace`（出走表と直前情報）だけです。結果と確定オッズは型にも実体にも含まれないので、`race.result` と書いた時点でコンパイルエラーになります。
- 直前情報は「未公開」という形を持ちません。公開前も枠だけが空で返ってきます。展示タイムが 1 艇も入っていなければ未公開とみなし、`preview` を `null` にします。
- 1R の水面気象は、後から取得すると「その日の最後の計測値」に置き換わっています。締切前には見えていなかった値なので、1R だけ `preview.weather` を `null` にします。
  - 2R 以降の水面気象は 1 つ前のレースの時点で固定されます。ただし順延などで、締切直前に表示されていた値と食い違う可能性は残っています（未検証）。
- 確定オッズを使う戦略は `lookahead: 'finalOdds'` を宣言します。確定オッズには締切後に集計される票が含まれるので、それを見て買うことは実際にはできません。検証結果には「リークあり」と表示します。

## 2. 払戻は払戻表から計算する

オッズ × 購入額ではなく、払戻表の金額（100 円あたり）で決済します。返還艇が出るとオッズと払戻が大きく食い違うことがあるためです。

## 3. 決着の分類と母数

| 決着 | 条件 | 戻ってくる金額 | 回収率の母数 |
|---|---|---|---|
| 的中 | 払戻表の組番と一致した | 払戻金 × 購入額 ÷ 100 | 入れる |
| 不的中 | どの組番とも一致しない | 0 | 入れる |
| 特払 | 賭式は成立したが的中票が無い（組番が空で 70 円） | 70 × 購入額 ÷ 100 | 入れる |
| 返還 | 舟券に返還艇（フライング・出遅れ・欠場）が含まれる | 購入額 | 外す |
| 不成立・中止 | 賭式が不成立（組番が空で元返しの 100 円）、またはレース中止（全賭式の払戻表が空） | 購入額 | 外す |
| 票なし | その賭式の払戻表に「組番はあるが金額が無い」行がある | — | 賭式ごと外す |
| 未確定 | 結果がまだ無い | — | 外す |

- 判定の順番は、未確定 → 中止 → 返還 → 不成立 → 票なし → 特払 → 的中・不的中です。
- 特払と不成立は、ラベルの文言ではなく金額（元返しの 100 円かどうか）で見分けます。ラベルは公式サイトの表記そのままで、ほかの文言が入る可能性があるためです。
- 特払のレースで的中目そのものを買っていた場合、実際には 0 票だった目なので、買っていれば唯一の的中票になっていました。その払戻は再現できないので、ほかの目と同じく 70 円として扱います。
- 票なしは保守的に扱っています。票なしの目を買っていた場合の払戻は定義できません。また、同じ賭式のほかの的中目の払戻も、票なしの目の分を総取りした結果です。そのため賭式ごと母数から外しています。票なしの目を買った舟券だけを外す、という別案もあります。

## 4. 集計

- 回収率 = 母数に入った払戻額 ÷ 母数に入った購入額
- 信頼区間: 同じレースの買い目は独立ではないので、舟券ではなくレースを単位にブートストラップします（パーセンタイル法、既定 2,000 回）。seed を固定しているので、同じ入力なら同じ区間が出ます。
- 最大ドローダウン: 締切順に損益を積み上げたとき、それまでの最高値から最も下がった幅です。
